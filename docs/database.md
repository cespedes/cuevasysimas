# Database

PostgreSQL, with the schema defined in the [goose](https://github.com/pressly/goose) migrations of
[`db/migrations/`](../db/migrations/). Everything is in the schema `catalogue` (the tables are named
with it in the code: `catalogue.places`, and nothing puts it on the search path, so a query that
forgets it fails); `public` has only goose's own table.

- `00001_baseline.sql` is the catalogue as it was when it left the intranet it was born in: the sum
  of its migrations 00061 to 00083, with the seeded reference data (the types, the subtypes and the
  geologies of places, and the zones of the world: the states, and for Spain its communities,
  provinces and municipalities). The sections below cite the numbers of those migrations: they are
  the history of each table, and the files are in the old repository.
- `00002_issuer_keys_and_references.sql` adds `issuers.public_key` and `place_references`.

**Conventions.** Every table has an `id bigint` generated by the database, except the join tables.
Instants are `timestamptz`. Every foreign key is `ON DELETE RESTRICT` (a test checks it), but the
zone of an element of the OpenStreetMap mirror, which is derived and set again by each load: nothing
cascades, and what is in use is refused by the database and, before it, by the code. Whatever
PostgreSQL can express with a constraint is in the database, and the tests use it for real.

**Files outside PostgreSQL.** The photos and documents of the places are bytes on disk, in
`PLACE_FILES_ROOT/<place or system id>/<file id>`, keyed by the id of the row, created once with
`O_EXCL` and **never rewritten**; the rows are in `place_files`.

**Seeding and copying data.** The catalogue of the intranet it came from is copied with `pg_dump
--data-only --schema=catalogue` into a database that has been migrated; the issuers come with no
key, which `issuer register` gives them. The place files are copied apart (the directory).

## The tables

The catalogue of places: caves and shafts, canyons, via ferratas, huts… A place has a type, one main
coordinate (in the place itself, so there is always one), a zone that says where it is and any
number of other points.

### `areas`

The zones of the world, as a tree of any depth: a country and, below it, whatever its administrative
divisions are (in Spain an autonomous community, a province and a municipality; in Andorra a
parish). Nothing in the code knows the levels: `kind` is the text that names each one, and a place
points at the most specific zone it is in, so its country, province… are its ancestors. The roots
are the states of the United Nations, all of them seeded (migration `00062`, with Spain down to its
municipalities, and the territories of ISO 3166-1 that are not states below the state that
administers them, migration `00077`; and Antarctica, Western Sahara and Taiwan, which no state
administers or whose administrator is disputed, as roots of kind "Territorio", migration `00078`);
anybody adds a zone below another, and an admin renames, merges and deletes them.

| Column | Type | Null | Default |
|---|---|---|---|
| `id` | bigint | no | identity |
| `parent_id` | bigint | yes |  |
| `kind` | text | no |  |
| `name` | text | no |  |
| `norm_name` | text | no |  |
| `code` | text | yes |  |
| `created_at` | timestamptz | no | now() |
| `created_by` | bigint | yes |  |

Notes on the columns:

- `parent_id`: The zone it is in; empty for a country.
- `created_by`: Who added the zone through the API (`areas.Repository.Create`); empty for the zones
  that the seeds load and for those added before the column existed.
- `kind`: The level, in the club's words: "País", "Comunidad autónoma", "Provincia", "Municipio"…
- `norm_name`: The name in lower case, without accents, and with every run of anything but letters
  and digits as one space ("Donostia/San Sebastián" is `donostia san sebastian`). It is what the
  search and the uniqueness of the names use, and `areas.Normalize` in Go writes it (a test checks
  that the seed has the same).
- `code`: An official code when there is one: ISO 3166-1 alpha-2 for a country, the INE's for a
  Spanish community, province or municipality (five digits: those of its province, then its own
  three).

Constraints:

- primary key (id)
- `parent_id` → `areas(id)`, and not its own parent; `created_by` is an account of the catalogue
  (`catalogue.accounts`), if the API added it
- `kind` and `name` are not blank, `norm_name` is not empty, and `code` is not blank when there is
  one
- unique `idx_areas_parent_name` on `(COALESCE(parent_id, 0), norm_name)`: below the same zone
  (among the countries, if there is none) two names that differ only in case, accents or punctuation
  are the same
- index `idx_areas_parent_id` on `(parent_id)`, and `idx_areas_norm_name` on `norm_name` (for the
  search)

Rules outside the database: only a country (or one of the three territories with no state) is a root
(the API never creates one), the name is at most 200 characters and the kind 60, a zone is only
deleted when nothing is below it and no place is in it (a country too), two zones are merged only
below the same one (two countries are), and the first zone below another one needs its `kind` said
(the rest take the one their siblings have).

### `place_types`

What kind of place something is. The `kind` decides what a place of the type has, as in
`material_types`: a cavity has a subtype, a depth and a horizontal length, and a cavity or a canyon
has a technical sheet. `has_state` says whether the places of the type have a state (open, permit
required…). The migrations seed Cavidad (`cave`), Cañón (`canyon`) and Vía ferrata, Refugio and Otro
(`general`); the first two are fixed, and an admin adds, renames and deletes the general ones. A
place has its state only if its type has one: Cavidad, Cañón and Vía ferrata do, and so may the ones
an admin adds.

| Column | Type | Null | Default |
|---|---|---|---|
| `id` | bigint | no | identity |
| `name` | text | no |  |
| `kind` | text | no | 'general' |
| `has_state` | boolean | no | false |
| `created_at` | timestamptz | no | now() |

Constraints:

- primary key (id)
- `name` is not blank
- `kind` is `cave`, `canyon` or `general`
- unique `place_types_id_kind_has_state_key` on `(id, kind, has_state)`: what `places` points at, so
  that the kind and the `has_state` of a place are always the ones of its type (neither changes
  after the type is created)
- unique `idx_place_types_name` on `lower(name)`: names are unique ignoring case

Rules outside the database: only a general type is created, renamed or deleted (409
`fixed_place_type` otherwise), and one that has places is not deleted (409 `place_type_in_use`).

### `place_subtypes`

What a cavity is (cueva, sima, torca, mina, abrigo…): a catalogue an admin edits, since there is no
end to the names. Only a place of the cave kind has one, and it has to. None is fixed and nothing in
the code depends on any. Migration `00066_place_cavities.sql` seeds Cueva, Sima, Torca, Mina and
Abrigo.

| Column | Type | Null | Default |
|---|---|---|---|
| `id` | bigint | no | identity |
| `name` | text | no |  |
| `created_at` | timestamptz | no | now() |

Constraints:

- primary key (id)
- `name` is not blank
- unique `idx_place_subtypes_name` on `lower(name)`: names are unique ignoring case

Rules outside the database: one that has places is not deleted (409 `subtype_in_use`).

### `place_geologies`

What a cave is formed in (limestone, gypsum, ice, lava…): a catalogue an admin edits, since there
are more kinds than anybody lists at once. Only a cave has one, and it is optional. None is fixed
and nothing in the code depends on any. The migration seeds Caliza, Yeso, Hielo and Lava (the usual
ones, first) and then Dolomía, Mármol, Sal, Arenisca, Cuarcita, Conglomerado and Granito.

| Column | Type | Null | Default |
|---|---|---|---|
| `id` | bigint | no | identity |
| `name` | text | no |  |
| `created_at` | timestamptz | no | now() |

Constraints:

- primary key (id)
- `name` is not blank
- unique `idx_place_geologies_name` on `lower(name)`: names are unique ignoring case

Rules outside the database: one that has places is not deleted (409 `geology_in_use`).

### `places`

| Column | Type | Null | Default |
|---|---|---|---|
| `id` | bigint | no | identity |
| `type_id` | bigint | no |  |
| `kind` | text | no |  |
| `has_state` | boolean | no |  |
| `name` | text | no |  |
| `alt_names` | text[] | no | '{}' |
| `state` | text | yes |  |
| `subtype_id` | bigint | yes |  |
| `system_id` | bigint | yes |  |
| `area_id` | bigint | no |  |
| `lat` | double precision | no |  |
| `lon` | double precision | no |  |
| `altitude_m` | integer | yes |  |
| `access` | text | yes |  |
| `description` | text | yes |  |
| `depth_m` | integer | yes |  |
| `horizontal_length_m` | integer | yes |  |
| `geology_id` | bigint | yes |  |
| `technical_sheet` | text | yes |  |
| `osm_type` | text | yes |  |
| `osm_id` | bigint | yes |  |
| `osm_seen` | jsonb | yes |  |
| `created_by` | bigint | no |  |
| `created_at` | timestamptz | no | now() |
| `updated_by` | bigint | no |  |
| `updated_at` | timestamptz | no | now() |
| `place_audience` | text | no | 'club' |
| `location_audience` | text | no | 'club' |
| `content_audience` | text | no | 'club' |
| `protected` | boolean | no | false |

Notes on the columns:

- `kind`: The kind of the place's type, kept here so that the checks below can use it.
- `has_state`: Whether the place's type has a state, kept here like `kind`.
- `alt_names`: The other names it is known by, a list (an array, not a table: a name has nothing
  else to say). Go keeps them trimmed, without blanks and without repeats ignoring case.
- `state`: Under which conditions the place can be visited: `open` (freely), `permit_required` (a
  permit has to be asked for first), `tourist` (it is run as an attraction and has to be paid for)
  or `closed` (it cannot be visited). Empty for a place whose type has no state.
- `subtype_id`: What a cavity is (cueva, sima…): empty for any other place.
- `system_id`: The system of cavities it is in, if it is in one (a cavity is in at most one).
- `area_id`: Where it is: the most specific zone known, at least the country.
- `lat`, `lon`: The main coordinate, WGS84, in degrees.
- `altitude_m`: Its altitude in metres above sea level (negative below it), when it is known.
- `access`, `description`, `technical_sheet`: Free text, shown with the little formatting of
  `js/rich-text.js`. The technical sheet says what has to be installed to go through the place.
- `depth_m`, `horizontal_length_m`: Of a cave, in metres.
- `geology_id`: What a cave is formed in.
- `osm_type`, `osm_id`: The OpenStreetMap element the place is, when it is one (see `osm_elements`).
- `osm_seen`: What OpenStreetMap said of that element when the place was linked to it or somebody
  last looked at what had changed (`POST /places/{id}/links/osm/review`): `{tags, lat, lon}`, a
  snapshot. The API compares it with the element as it is now to tell what changed (`osm_changes`);
  a load of the mirror never touches it. Empty if the place is not an element (migration
  `00070_place_osm_seen.sql`, which gave the places already linked the element as it was then).
- `updated_by`, `updated_at`: The last change of the place or of any of its points; the same as the
  creation until there is one. They are set by the Go service.
- `place_audience`, `location_audience`, `content_audience`: Who may see each of the three levels,
  the club's members alone (`club`) or anybody (`public`): the place itself (that it exists, with
  its name, type, state, zone and measures), where it is (the main coordinate, the other points and
  how to get there) and what is said and shown of it (the description, the technical sheet and the
  files). Everything is `club` until an admin or a board member opens it (migration `00082`); who
  wrote it is never public (`places.Visibility`).
- `protected`: Locks the place closed (bats, archaeology, private land): nothing of it may be
  public.

Constraints:

- primary key (id)
- `(type_id, kind, has_state)` → `place_types(id, kind, has_state)`
- `area_id` → `areas(id)`, `geology_id` → `place_geologies(id)`, `subtype_id` →
  `place_subtypes(id)`, `system_id` → `place_systems(id)`
- `(osm_type, osm_id)` → `osm_elements(osm_type, osm_id)`, `ON DELETE RESTRICT`: the element is in
  the mirror
- `places_osm_both_or_none`: `osm_type` and `osm_id` are both there or both empty
- unique `places_osm_element_key` on `(osm_type, osm_id)`: an element is at most one place
- `places_osm_seen_needs_element`: there is a snapshot only if there is an element
- `created_by` and `updated_by` → `catalogue.accounts(id)`: who added it and who last changed it
- `name` is not blank
- `state` is `open`, `permit_required`, `tourist` or `closed`, or empty
- `state_for_types_with_state`: `has_state` is true exactly when there is a state
- `subtype_for_caves`: `kind = 'cave'` exactly when there is a subtype
- `system_only_for_caves`: `kind = 'cave'` or there is no system
- `places_audiences_known`: the three audiences are `club` or `public`
- `places_location_not_more_open_than_place` and `places_content_not_more_open_than_place`: a level
  is `club` unless the place is `public`
- `places_protected_is_closed`: a protected place has the three at `club`
- `alt_names_not_too_many`: at most 50 names (Go allows 20)
- `lat` between -90 and 90, `lon` between -180 and 180, `altitude_m` between -500 and 9000
- `depth_m` and `horizontal_length_m` not negative
- `measures_only_for_caves`: `kind = 'cave'` or both measures are empty
- `geology_only_for_caves`: `kind = 'cave'` or there is no geology
- `technical_sheet_only_for_caves_and_canyons`: `kind` is `cave` or `canyon`, or there is no sheet
- index `idx_places_type_id` on `(type_id)`, `idx_places_area_id` on `(area_id)`,
  `idx_places_geology_id` on `(geology_id)`, `idx_places_subtype_id` on `(subtype_id)`,
  `idx_places_system_id` on `(system_id)` and `idx_places_lat_lon` on `(lat, lon)`

Rules outside the database: the zone is given and exists (`places.Service` checks it before the
statement), the coordinates are given (a missing one is not zero), the altitude (400
`invalid_altitude`) and the measures stay within limits that only catch a typo (-500 to 9000 m of
altitude, 20000 m of depth and 2000000 m of horizontal length), and what a place has fits the kind
of its type (400 `invalid_place_fields`; `places.Service` checks it before the statement, the
constraints are the backstop). A place may change to any type whose kind fits its fields.

### `place_points`

The other points of a place: where to leave the car, where the approach starts, a waypoint, each of
the accesses… Nothing cascades: `places.Repository.DeletePlace` deletes the points with the place,
in one transaction.

| Column | Type | Null | Default |
|---|---|---|---|
| `id` | bigint | no | identity |
| `place_id` | bigint | no |  |
| `kind` | text | no |  |
| `name` | text | yes |  |
| `lat` | double precision | no |  |
| `lon` | double precision | no |  |
| `altitude_m` | integer | yes |  |
| `note` | text | yes |  |
| `created_at` | timestamptz | no | now() |

Constraints:

- primary key (id)
- `place_id` → `places(id)`
- `kind` is `parking`, `approach`, `waypoint`, `access` or `other`
- `name` is not blank when there is one
- `lat` between -90 and 90, `lon` between -180 and 180, `altitude_m` between -500 and 9000 (metres
  above sea level, when it is known)
- index `idx_place_points_place_id` on `(place_id)`

### `place_systems`

A system of cavities connected underground (migration `00067_place_systems.sql`): a name, a
description and, through `places.system_id`, its cavities. Its files are in `place_files`.

| Column | Type | Null | Default |
|---|---|---|---|
| `id` | bigint | no | identity |
| `name` | text | no |  |
| `description` | text | yes |  |
| `created_by` | bigint | no |  |
| `created_at` | timestamptz | no | now() |
| `updated_by` | bigint | no |  |
| `updated_at` | timestamptz | no | now() |

Constraints:

- primary key (id)
- `name` is not blank
- `created_by`, `updated_by` → `catalogue.accounts(id)`
- unique `idx_place_systems_name` on `lower(name)`: names are unique ignoring case

### `place_files`

The metadata of the photos and documents attached to a place or to a system (migrations
`00063_place_files.sql` and `00067`); the bytes are on disk, in `PLACE_FILES_ROOT/<place or system
id>/<row id>`, and never rewritten. A row id is unique among the files of both, so two files never
share a path although a place and a system may share a directory number.

| Column | Type | Notes |
|---|---|---|
| `id` | bigint | identity |
| `place_id` | bigint | → `places(id)`, `ON DELETE RESTRICT` (the service deletes the rows first); empty for a file of a system |
| `system_id` | bigint | → `place_systems(id)`, `ON DELETE RESTRICT`; empty for a file of a place |
| `title` | text | the caption, optional |
| `file_name` | text | not blank; the name of the uploaded file |
| `content_type` | text | not blank; decided from the bytes |
| `file_size` | integer | greater than 0 |
| `uploaded_by` | bigint | → `catalogue.accounts(id)` |
| `created_at` | timestamptz | default `now()` |

- `file_of_a_place_or_a_system`: exactly one of `place_id` and `system_id` is there
- indexes `idx_place_files_place_id` on `(place_id)`, `idx_place_files_system_id` on `(system_id)`
  and `idx_place_files_uploaded_by` on `(uploaded_by)`

### The accounts of the catalogue: `catalogue.accounts`, `issuers` and `account_identities`

Who acts on the catalogue, kept apart from any client's table of people (migration `00083` of the
old repository): what the places, the systems, the files and the zones keep of who made something is
the id of an account.

`accounts`:

| Column | Type | Null | Default |
|---|---|---|---|
| `id` | bigint | no | identity |
| `kind` | text | no |  |
| `display_name` | text | no |  |
| `created_at` | timestamptz | no | now() |

- `kind`: `person` (shown as the author of a change) or `service` (a client of the catalogue: the
  intranet of the club is the first).
- `display_name`: How it is shown, not blank. For a person it is the name the issuer gave the last
  time they acted (for the club, their login), so a person who changed it is shown by the new one
  from then on, on everything they ever made.
- primary key (id); `kind` is `person` or `service`

`issuers`: the services that vouch for the people they send. `issuer` (text, the key: the intranet's
is `katiuskas-intranet`) and `account_id` (→ `catalogue.accounts(id)`, unique: the service account
that answers for it). An assertion of an issuer that is not here is refused (403).

`account_identities`: how an issuer knows a person. `issuer` (→ `issuers`), `subject` (text: what
the issuer calls the person, for the intranet `users.subject`, a uuid that says nothing of how it
stores them) and `account_id` (→ `catalogue.accounts(id)`); the key is `(issuer, subject)`, and
index `idx_account_identities_account_id`. The account of a person is made the first time they
change something, never before (`accounts.Service.Ensure`). The subject is in no other table of the
catalogue.

All the foreign keys are `ON DELETE RESTRICT`, so an account that made something is never deleted.

`issuers` also has `public_key` (`bytea`, 32 bytes, nullable: migration `00002`), the Ed25519 key
that the issuer signs its assertions with (`internal/assertion`); an issuer with none cannot vouch
for anybody. `issuer register` gives it.

### `place_references`

A client says that it uses a place (an activity went there, for the intranet), and the catalogue
does not delete a place that any client uses (migration `00002`).

| Column | Type | Null | Default |
|---|---|---|---|
| `place_id` | bigint | no |  |
| `issuer` | text | no |  |
| `ref_key` | text | no |  |
| `created_at` | timestamptz | no | now() |

- primary key `(place_id, issuer, ref_key)`: the key is the client's own, opaque to the catalogue,
  and the same key of another issuer is another reference
- `place_id` → `places(id)` and `issuer` → `issuers(issuer)`, both `ON DELETE RESTRICT`: the key
  backs up the check that `places.Service.DeletePlace` makes, for a reference made at the same time
  as a delete
- `ref_key` is not blank and has at most 200 characters; index `idx_place_references_issuer`

### `osm_elements`

A local copy of the elements of OpenStreetMap that matter to the club (migration
`00069_osm_mirror.sql`; `docs/osm-integration.md` says why): caves, canyons and mines, which are
what the club does, and huts and via ferratas. It is a mirror: only `cmd/osmsync` writes it, from
the extracts that Geofabrik publishes, and the API only reads it (`GET /osm/elements`). It is apart
from `places` and joined to it by the type and the id of the element, so that what is
OpenStreetMap's and what is the club's stay separate.

| Column | Type | Null | Default |
|---|---|---|---|
| `osm_type` | text | no |  |
| `osm_id` | bigint | no |  |
| `version` | integer | no |  |
| `osm_timestamp` | timestamptz | no |  |
| `category` | text | no |  |
| `lat` | double precision | no |  |
| `lon` | double precision | no |  |
| `tags` | jsonb | no |  |
| `geometry` | jsonb | yes |  |
| `content_hash` | text | no |  |
| `source` | text | no |  |
| `first_seen_at` | timestamptz | no | now() |
| `fetched_at` | timestamptz | no | now() |
| `changed_at` | timestamptz | no | now() |
| `deleted_at` | timestamptz | yes |  |
| `area_id` | bigint | yes |  |

Notes on the columns:

- `osm_type`, `osm_id`: What the element is: an id is only unique among those of its type, so both
  make the key (node 123 and way 123 are not the same).
- `version`, `osm_timestamp`: Of the element as it was downloaded, and when it was last edited.
- `category`: What the filters of the loader say it is: `cave`, `canyon`, `mine`, `hut` or
  `via_ferrata`.
- `lat`, `lon`: The point: a node itself, or a point inside the shape of a way or a relation (not
  the average of its corners, which can be outside an L-shaped building), or the middle of a line
  (of a canyon, the middle of the ways of its stream laid end to end: provisional, since the
  entrance and the exit of a canyon are what the club will want, and OpenStreetMap does not have
  them).
- `tags`: All the tags as they are. `geometry`: the GeoJSON of the outline of a way or a relation (a
  `MultiLineString`, one line per way, for a canyon), empty for a node.
- `content_hash`: A hash of the tags, the point, the outline and the zone, which tells a load that
  something changed even when the version did not (a node of a way that moved does not change its
  version).
- `source`: The extract that last had it (`spain`, `canary-islands`).
- `fetched_at`, `changed_at`: When a load last confirmed it, and when one last found it different
  (or marked it as gone).
- `deleted_at`: Set when the element is no longer in its extract (deleted from OpenStreetMap, or no
  longer matching the filters); the row stays, since a place may point at it, and the mark is
  cleared if it comes back.
- `area_id`: The zone (a row of `areas`) the point is in, worked out on each load from the
  boundaries of the same extract; in Spain it is the municipality whose `ref:ine` is the `code` of
  the zone. Empty if it is in none known (the sea, a country whose zones are not in the catalogue).
  It is the one foreign key that is `ON DELETE SET NULL` and not `RESTRICT`: what it holds is
  derived and the next load works it out again, so deleting a zone is never stopped by the mirror,
  and merging two moves the elements to the zone that stays (migration `00072_osm_area.sql`).

Constraints:

- primary key (osm_type, osm_id)
- `area_id` → `areas(id)`, `ON DELETE SET NULL`
- `osm_type` is `node`, `way` or `relation`; `category` is `cave`, `canyon`, `mine`, `hut` or
  `via_ferrata`
- `lat` between -90 and 90, `lon` between -180 and 180
- indexes `idx_osm_elements_lat_lon` on `(lat, lon)` and `idx_osm_elements_source` on `(source)`,
  both only over the rows that are not marked as gone, and `idx_osm_elements_area_id` on
  `(area_id)`, which deleting a zone needs to find its elements

### `osm_sync_runs`

One row per load of an extract by `cmd/osmsync`, written when it starts and closed when it ends, so
that a load that fails is in the log with its error.

| Column | Type | Null | Default |
|---|---|---|---|
| `id` | bigint | no | identity |
| `source` | text | no |  |
| `source_timestamp` | timestamptz | yes |  |
| `started_at` | timestamptz | no | now() |
| `finished_at` | timestamptz | yes |  |
| `status` | text | no | `running` |
| `added`, `changed`, `deleted`, `unchanged` | integer | no | 0 |
| `error` | text | yes |  |
| `unknown_zones` | integer | no | 0 |
| `unknown_zone_codes` | text | yes |  |

`unknown_zones` is how many municipal boundaries of the extract have no zone in the club's
catalogue, and `unknown_zone_codes` the first twenty of their INE codes, separated by commas: the
sign that the list of municipalities is behind OpenStreetMap's. `source_timestamp` is the date of
the data in the extract (its replication timestamp): a load whose extract is not newer than the one
of the last successful load of the same source does nothing. `status` is `running`, `ok` or
`failed`. Index `idx_osm_sync_runs_source` on `(source, started_at DESC)`.
